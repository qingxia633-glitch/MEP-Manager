# MEP-Manager

面向机电安装预算的图纸理解、路径推导与工程量计算工具，首个重点场景为地下车库电气安装算量。

## 项目定位与当前状态

核心目标是模拟安装预算人员综合理解图纸的过程：从设计说明、配电系统图获取供电关系和电缆信息，将设备编号与平面图位置对应，再结合桥架网络推导实际可行的电缆路线。

平面图可能只画出配电箱和桥架，没有画出完整电缆。因此，软件需要根据供电关系推导路径，不能仅统计已有电缆线，也不能用两台设备间的直线距离代替敷设长度。

当前已有可离线运行的PowerShell/C#实验模块及真实样本回归，覆盖图纸证据、设备角色、类别集合、逻辑网络、二维Routing和候选路径。尚未完成正式回路身份、三维路径和工程量准入。当前进度、冻结结论与后续优先级见 [工作状态（2026-10-03）](PROJECT-STATUS-20261003.md)。

下文保留早期配电箱/桥架原型设计，属于历史路线规划；其中“待实现”、依赖环境和资料需求不代表当前仓库状态。当前回归入口为 `model-core/tests/Run-Regressions.ps1`，需使用PowerShell 7。

## 核心业务流程

1. 读取 CAD 中的图层、文字、块、属性和线段／多段线。
2. 识别配电柜、配电箱的编号及平面位置，并保留原图实体来源。
3. 识别主桥架、支桥架、转弯、分支、交叉及标高信息，建立可通行的拓扑网络。
4. 将供电关系中的起点、终点关联到平面设备，再确定设备与桥架的接入位置。第一阶段由人工指定设备编号，不自动推断供电关系。
5. 在满足连通性、标高和已知通行限制的桥架网络内寻找候选路线。
6. 由人工检查、修改和确认路线；自动生成的结果默认处于待校核状态。
7. 路线确认后，分别计算水平长度、垂直长度、进出箱长度、必要预留和损耗，形成可追溯的电缆工程量。

最短路径只是候选路线，不等于预算人员已经认可的合理敷设路线。未知标高、接入方式或连接关系必须显式提示，不能默认为零或自动补成已确认数据。

## 第一个可运行原型：技术方案（待实现）

### 验证目标与输入范围

仅验证：从一张真实地下车库 CAD 图中识别配电箱和桥架，计算两个指定配电箱之间沿桥架行走的候选路线。

- 首版采用本地 Python 命令行程序，无服务器和复杂界面。
- 优先接收模型空间中的 DXF。DWG 需由现有 CAD 软件另存为 DXF；若需要转换工具，先说明工具、用途和许可要求，再经用户确认安装。
- 输入包括：原始图纸、两个设备编号，以及 JSON 配置中的单位、设备图层／块名、桥架图层和识别容差。具体规则与数值根据样图确认，不预设通用图层名称或编号格式。
- 原图保持只读，输出写入独立目录。外部参照需随图提供或在导出副本中绑定；缺失参照、自定义代理实体、仅有图片的图纸须报告限制，不能声称已经完整解析。
- 第一版不自动阅读系统图，不识别完整供电关系，不计算最终计价工程量。

### 处理架构

```text
DXF + 图纸配置 + 起终点编号
  → 实体读取与坐标／单位归一化
  → 配电箱候选及桥架中心路径识别
  → 连接关系校验与桥架拓扑图
  → 设备接入桥架
  → 受约束的最短路径
  → 路线 DXF 副本 + JSON／CSV 长度及诊断报告
```

模块按读取、识别、拓扑、寻路、输出划分，采用内存数据结构和本地文件。模块名称和目录等到开始实现时再落地。

1. **读取和归一化**：读取 `INSERT`、`ATTRIB`、`TEXT`、`MTEXT`、`LINE`、`LWPOLYLINE`、`POLYLINE` 等实体。处理块的平移、旋转、缩放和嵌套，统一到世界坐标；保留实体句柄及块引用链。核对图纸单位与已知尺寸，最终长度统一输出为米。图纸单位不明时要求补充，不能直接按毫米解释。
2. **设备定位**：优先利用已确认的块名和属性编号；再用文字与邻近设备几何的关联提出候选。保留设备编号、位置、图层、来源及匹配依据。重复编号、多个候选或编号缺失时返回待确认，不自动选择最近对象。设备块插入点仅作为定位点，不直接当作实际电缆进箱点。
3. **桥架识别**：按确认的图层、实体类型和画法筛选候选。已有中心线时直接提取；双线桥架需依据宽度、平行性和转弯／分支关系提取中心路径，不能把两条边线当作两条通道。若样图采用双线，需实现该样图的有限规则并验证；无法可靠提取的部分标为待补充。人工补绘中心线只能验证寻路模块，不能算作自动桥架识别通过。
4. **拓扑建立**：节点表示端点、分支和确认的连接点，边表示桥架中心路径，保存几何、水平长度、标高及来源。在明确容差内处理微小端点误差，并记录修正。T 形接入需切分边；平面交叉不必然连通，不同标高默认不连通，只有明确的连接或人工确认才建边。标高不明的交叉保留待确认状态；不能用吸附容差掩盖真实断点。圆弧／带 bulge 的多段线保留弧长或按明确误差离散，不能直接以端点弦长替代。
5. **设备接入**：在同层、允许的桥架段上生成接入候选，投影到段内时切分对应边。邻近距离仅作候选排序，不能作为接入有效的唯一依据。真实接入路径无法从图中确定时，请人工指定接入点和引接折线；不可默认穿墙或跨越障碍。引接段与桥架段分别计长。
6. **寻路**：先排除明确不可通行的边，再按几何长度加权运行 Dijkstra。首版限定已确认的同层网络；涉及标高变化而无连接数据时报告待补充。不可达时返回断网诊断，不退化为两点直线，也不自动跨接间隙。有多条等长路线时记录所选路线待人工检查；主支桥架优先级等工程偏好后续按业务规则补充。
7. **输出**：在新 DXF 副本的专用图层标出设备、桥架候选、路径、接入点和待确认点；用 JSON 保存有序路线坐标、节点／边、来源、配置、分段长度及状态，用 CSV 输出长度明细。使用现有 CAD 查看和检查结果，第一阶段可通过调整配置中的连接、禁行边及接入点后重算，不开发路线编辑界面。

### 长度和结果状态

- 原型主要输出桥架路线的水平几何长度；有明确引接折线时，另列起点和终点引接水平长度。
- 已知同层水平长度 = 桥架路径水平长度 + 两端已确认的水平引接长度。缺少引接路径时只报告已知部分，不能标为完整设备间长度。
- 垂直长度、进出箱长度、预留和损耗分别留作待补充项，不擅自假定数值；引接中已计入的部分后续不能重复计量。
- 后续依据确认的规则，把水平、垂直、进出箱和预留分项组成基础量，再按明确的损耗口径计算，不在原型中固定统一损耗率。
- 结果区分“候选路线待校核”“输入／拓扑待确认”“不可达”。任何自动输出都不直接成为最终电缆工程量；人工确认须记录确认内容及所对应的图纸、配置和路线版本。

### 实施顺序与验收

1. 收到样图后先只读检查实体和图层，确认单位、设备编号、桥架画法、接入及交叉规则。
2. 使用标准库 `unittest` 为各功能增加小型单元测试；修复缺陷时先增加复现测试。覆盖转弯与分支、T 形接入、断网、异标高交叉、容差边界、块变换、重复设备编号和长度单位；样图含双线／圆弧时增加对应测试。
3. 按读取 → 识别 → 建图 → 接入 → 寻路 → 输出逐步实现，不先搭界面。
4. 在真实样图上运行，与用户标注的设备、桥架及参考路线比对；长度采用人工认可的路线分段复算，容许误差根据图纸精度事先约定。
5. 验收要求：两个设备匹配正确；桥架识别与原图一致；路径只通过已确认连接；分段长度之和与总长一致；有歧义或断网时明确报告；原始图纸不被改写。保存输入版本标识和配置，使结果可复现。

通过这一原型只说明选定样图与画法上的识别和寻路可行，不代表已经适配所有 CAD 图纸或实现自动预算。

## 下一步需要的测试资料

1. 一张可用于测试的真实地下车库电气平面图，优先 DXF；若只有 DWG，请提供版本信息，并说明是否能用现有 CAD 导出 DXF。可先提供脱敏局部，但需包含两个设备及连接它们的完整桥架区域。

3. 图纸单位或一段已知实际尺寸，以及桥架、设备对应图层／块名（如不清楚，可由样图检查后共同确认）。
4. 与这条路线相关的桥架标高、交叉是否连通、设备如何接入桥架的说明；不明确的地方请标为未知。
5. 如使用外部参照，提供相关文件或绑定后的导出副本。设计说明和配电系统图可作为辅助资料，首版不强制自动解析。
6. 若已有人工算量结果，请注明是否包含上下翻、进出箱、预留和损耗，避免拿不同口径比较。
